# path

Cross-platform path manipulation utilities that normalize between POSIX and native (Windows) separators.

Grouped into four concerns: joining ([`join`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-join), [`joinPosix`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-joinPosix), [`joinPath`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-joinPath)), normalization ([`normalizePath`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-normalizePath), [`normalizeToForwardSlashes`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-normalizeToForwardSlashes), [`normalizeToNative`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-normalizeToNative), trailing-slash helpers), resolution ([`resolvePath`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-resolvePath), [`resolveRealPath`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-resolveRealPath), [`resolveFromWorkspace`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-resolveFromWorkspace), [`relativePath`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-relativePath), [`workspaceRelativePath`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-workspaceRelativePath), [`offsetFromRoot`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-offsetFromRoot), [`isAbsolute`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-isAbsolute)), and segment extraction ([`getDirname`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-getDirname), [`getBasename`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-getBasename), [`getExtension`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-getExtension), [`getFileNameWithoutExtension`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-getFileNameWithoutExtension), [`parsePath`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-parsePath), [`pathSegments`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-pathSegments)).

Every path is one of two kinds. A portable path acts as data: a map key, a configuration value, a project root, a message or a glob. It is relative to a known root and uses `/` on every platform, so the same value means the same thing on Windows and POSIX. A native path exists only to reach the file system: absolute, built by the platform, and never compared or stored.

Convert at the boundary between the two. [`normalizePath`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-normalizePath) turns a native path into its portable spelling, [`relativePath`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-relativePath) and [`workspaceRelativePath`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-workspaceRelativePath) produce a portable path anchored at a root, and [`join`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-join) or [`normalizeToNative`](https://www.hyperfrontend.dev/docs/libraries/project-scope/core/path/#api-normalizeToNative) turn a portable path back into a native one for the disk.
