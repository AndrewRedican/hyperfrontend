# models

Registry data models: registries themselves, package metadata, version metadata, and maintainer records.

[`Registry`](https://www.hyperfrontend.dev/docs/libraries/versioning/registry/models/#api-Registry) and [`RegistryConfig`](https://www.hyperfrontend.dev/docs/libraries/versioning/registry/models/#api-RegistryConfig) describe a configured registry endpoint (URL, scope, auth headers) used by the registry clients. [`PackageInfo`](https://www.hyperfrontend.dev/docs/libraries/versioning/registry/models/#api-PackageInfo) (built via [`createPackageInfo`](https://www.hyperfrontend.dev/docs/libraries/versioning/registry/models/#api-createPackageInfo)) carries package-level metadata: name, dist-tags, versions list. [`VersionInfo`](https://www.hyperfrontend.dev/docs/libraries/versioning/registry/models/#api-VersionInfo) (built via [`createVersionInfo`](https://www.hyperfrontend.dev/docs/libraries/versioning/registry/models/#api-createVersionInfo)) carries per-version metadata: version string, dependency declarations, dist (tarball + integrity), and `Maintainer[]`. The factories produce normalized objects regardless of the registry's exact payload shape so downstream code can rely on a single model.
