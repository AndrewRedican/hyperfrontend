# 15 — Koi Pond ⭐

The visual-thesis flagship: a tranquil top-down zen pond where **seven koi, each rendered by an independently implemented app in a different framework**, swim in layered transparent full-viewport frames over a host-owned pond. Calm ambient motion, no controls; the only interaction is disturbing the water — a click/tap ripples the surface and nearby fish scatter. Hovering a fish reveals its framework and the URL of the app rendering it.

**Type** Execution · **Status**: In flight (built by hand; deliberately jumps the [06](06-demo-2-and-generator.md) generator gate, like the two demos before it). Committed: the shared lib with the 3D koi + three adapter, the workbench, and seven bare fish scaffolds. In working tree: the pond host, docs-site wiring, and a superseded 2D fish implementation kept only as migration reference. The koi was re-architected 2026-08-08 from a flat SVG to a lofted 3D three.js mesh; the decisions table below was re-grilled the same day.

Supersedes the earlier plugin-seam koi concept (host repositioning small feature containers); fish now own their motion inside full-viewport frames and the host owns the environment.

## What it proves

Multiple independently implemented apps running simultaneously, composited into **one continuous scene**: shared visual model (depth, light, water), host-mediated coordination (disturbances, proximity, depth transitions), framework isolation intact — and, via the pond's dual role below, the first live **gallery → host/hostee → fish** nesting chain.

## Core simulation model (summary)

- **Virtual pond**: a stable coordinate system snapshotted from the screen when the scene opens, extending margins (sized in fish lengths) beyond every edge; the presenting frame is only a _view_ — a window rect the pond announcement carries separately, recomputed on resize while the world never moves. Gallery card, expanded overlay, and debug panel are different windows onto the same pond. Fish may leave the visible window; only the virtual boundary triggers forward-aware, curving avoidance — never clamping or bouncing.
- **Procedural koi**: a renderer-free 3D body — a table of cross-sections lofted into a shell, posed by a spine built from curvature and then integrated (arc length exactly conserved), markings generated in the koi's own body coordinates so they hold still while the body flexes; four visibly distinct states (relaxed, turning, escape, depth transition) expressed as behaviour → curvature. Each fish app pairs its own steering brain with its own renderer; the lib is a vocabulary, not a simulation engine.
- **Identity & behaviour**: per-fish palette derived from the framework's brand colours; normalised 0–1 behavioural traits (cruise speed, shyness, social affinity, awareness, directional caution, depth-change willingness, reaction intensity, turn responsiveness) + physical profile.
- **Collision**: compact reported outlines (spine samples + half-widths in pond px, never render geometry); host broad-phase → pairwise narrow-phase predictive avoidance; turn / slow / accelerate / pass-above / pass-below.
- **Surface ripples**: only the highest-depth fish may request them; fish report compact ripple requests, the host validates/rate-limits, the surface-water layer renders. Click ripples are host-owned.
- **Accessibility**: mouse + touch; keyboard/AT-accessible fish roster equivalent for hover identity; `prefers-reduced-motion` damps oscillation, escape intensity, distortion, and depth-scale change without losing the functional demonstration.

The full behavioural/physical/rendering specification lives with the implementation effort; this plan records the architecture so the roadmap stays concise.

## Known constraints and risks

- **Hardened into findings**: [F-009](findings/009-dev-server-directory-index-blocks-multi-app-origin.md) (`hf dev` won't serve `/sub-path/` — each frame mounts an explicit `fish-<name>/index.html`, two URLs per app), [F-010](findings/010-debug-port-not-configurable-and-collides.md) (debug UI port), [F-011](findings/011-message-delivery-collapses-across-concurrent-channels.md) (v1 message-delivery collapse across concurrent channels — root-caused; the pond's inner channels drop v1).
- **Seven WebGL contexts**: one per fish iframe (iframes get their own budgets, and the fish are ~3 draw calls each) — but the host must stay off WebGL, and only one live scene may exist at a time (see Gallery row).
- **Body reset interplay**: fish apps must paint nothing on `body`/root backgrounds — any paint blanks the pond behind that frame.
- **Reveal choreography**: frames stay hidden until each session opens (staggered handshakes) — host-side curtain until all seven `open` events land, force-lifted at a deadline.
- **Tarball churn**: a koi-lib bump touches every consumer's `package.json` + lockfile — `demo-koi-lib:refresh` regenerates all in one pass and `:verify` fails loudly on drift, because a bare `npm install` silently no-ops on a same-version repack. Each consumer with dependency-checks needs the lib's exact name in `ignoredDependencies`.
- **Never `serve -s`** (or any SPA rewrite) against the built site — each missing `/fish-*/` request becomes a nested copy of the pond.
- **Devcontainer**: ten `npm install`s at `parallel: 1` — serialize; expect the demo family to dominate install time.
